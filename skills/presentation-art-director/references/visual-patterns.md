# Visual pattern library

Choose patterns by relationship. Keep them editorial and minimal.

## Broken vs connected journey
Use for fragmented today-state vs coherent future-state experiences.
- Today: interrupted path, broken continuity, visible handoffs
- Future: continuous rail/path
- Avoid rows of boxes

## Blueprint / topology
Use for explaining structural causes.
- Entry nodes → lanes/domains → capability layer
- Show duplication or separate access paths when fragmentation is the point
- Avoid dense engineering architecture

## Layered platform
Use for shared foundations enabling many experiences.
- Products/domains above
- reusable foundations below
- new experiences plug into shared layer
- visually distinguish “shared” from “already unified” when needed

## One-to-many inheritance
Use for reusable pattern/capability propagation.
- One source/foundation
- multiple inheritors
- let direction and branching carry meaning

## Convergence
Use for VOC, research, evidence, or signals pointing to the same conclusion.
- multiple sources enter
- one or a few common themes emerge
- destination is visually dominant

## Root cause → symptoms
Use when one structural issue manifests in several experienced problems.
- one root node
- branching consequences
- keep root visually heavier than symptoms

## Causal chain
Use when metrics/actions have a logical sequence.
- left-to-right or top-to-bottom
- show mechanism, not mere chronology
- avoid implying causality if evidence is only correlational

## Accumulating burden
Use when complexity compounds.
- simple starting job
- sequential layers/branches add cognitive load
- visually show expansion or burden, not equal cards

## Tension spectrum
Use for judgment vs automation, guidance vs control, standardization vs flexibility.
- one or two axes
- label poles clearly
- use position as meaning
- avoid boxed 2×2 consulting matrices unless quadrants truly matter

## Feedback loop
Use when learning feeds the next cycle.
- ensure the final node visibly returns to the first
- make decision/control points explicit
- do not merely arrange five cards in a circle

## Decision gate / routing model
Use for prioritization or intake.
- inputs → assessment → disposition
- show the point where a choice is made
- outcomes may branch after the gate

## Cross-cutting ownership
Use for horizontal team/function spanning vertical domains.
- vertical lanes = domain ownership
- horizontal layer = connective ownership
- make overlap intentional and legible

## Gated sequence
Use for learning/validation before scaling.
- stages unlock sequentially
- evidence gate between stages
- dates secondary to learning/decision logic

## Equation / strategic payoff
Use for “A + B = C”.
- make the equation itself dominant
- avoid three equal cards
- supporting copy should be subordinate

## Editorial quote
Use for external validation.
- large typographic quote mark
- quote is hero
- publication logo/source below
- generous negative space
- no card, panel, or decorative stock treatment
- source logos may be normalized to deck palette if permitted

## Data story
Start with the insight.
- highlight the delta/trend/outlier
- mute supporting data
- annotate directly instead of long legends
- bar for comparison/rank, line for trend, dot plot for precise comparison, waterfall for contribution
